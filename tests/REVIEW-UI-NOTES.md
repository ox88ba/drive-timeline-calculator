# 移动布局独立复审结果

日期：2026-09-25。最新结论见文末“最终复验定稿”；前文保留初次复审证据，所列三项P1及风险换行现已在本轮样本中修复。

## 方法与范围

只读审查 mobile-ux.css/js、app.js decorateCompactCard 和既有天空样式。以 tests/mobile-layout.test.cjs 的本地假数据与请求拦截为基础，在临时脚本中补充计算样式、首屏及卡片截图；隔离 Chrome、临时浏览器上下文、所有非 local.test 请求被中止，API返回假数据。未访问真实行程、未触发付费AI或真实导航、未改产品代码。

独立运行375/390/393/430/1280宽度的既有断言全部通过：根页面无横向溢出、首屏日期位置、停留展开及累计更新、更多菜单、地图inert切换。390宽度截图分别记录首屏、卡片和菜单；通过 .shell.scrollTop 定位卡片并等待动画稳定，未以滚到底部截图代替首屏。

## 待修复

1. **P1：夜间卡片新标题、更多入口和停留摘要使用深色字。** mobile-ux.css:5、14、20 继承页面色，旧timeflow规则只覆盖input等旧元素；390测试中地点标题及停留摘要计算色均为 rgb(28,35,51)，夜间背景上几乎不可读，截图确认。修正：地点与更多入口使用抵达天空墨色；停留摘要、住宿复选框文字和说明使用停留带专属浅色，不能直接沿用白天天空墨色。验收：深夜、黎明、正午、黄昏的标题/摘要/展开内容均可读，普通文字对比度至少4.5:1。

2. **P1：白底更多菜单被旧天空规则覆盖为浅色字。** mobile-ux.css:16–17选择器优先级低于timeflow.css:58–62等旧规则。实测普通菜单项为浅色墨色75%透明，删除仍为#ff9aa1，白底上几乎不可读；菜单项高度44px虽通过却不能代表可用。修正：提高菜单专属前景/背景规则优先级，隔离天空继承；删除独立分组。验收：三种天空下菜单始终深字白底，删除深红，焦点与禁用状态可区分。

3. **P1：首屏日期/时间在屏内，但文字被窄输入框截短。** mobile-ux.css:3将字号提高至16px，styles.css窄屏仍使用99px/64px列宽。390首屏截图中日期只显示2030/09/…，时间显示18:…，未能完整呈现。修正：日期时间独立一行或换成足够宽的两列；避免单靠date.bottom<844验收。验收：375/390/393/430均完整显示日期与小时分钟，长出发地不挤压输入。

4. **P2：风险容器换行规则未命中。** mobile-ux.css:24针对.tf-daylight-row，实际DOM为.arrival-hints；计算flex-wrap仍为nowrap（voyage.css:876）。子标签文字可换行不等于标签组可换行。修正实际容器选择器；以长“距日出/日落”与海拔提示组合验证多行无重叠。

5. **P2：文字放大检查存在根节点测试盲区。** 对页面各元素先读取计算字号、再分别翻倍的200%压力测试中，根宽仍390，但.shell的scrollWidth=473、clientWidth=390；其overflow-x:hidden会掩盖内部超宽。此为人工字体压力测试，不等同Safari字体放大。建议增加.shell及关键字段的边界/可见性检查，并补Safari200%文字放大实测；不要以根scrollWidth通过宣称字体放大通过。

## 修复后复验（2026-09-25，第二次）

沿用隔离Chrome、外网全部拦截及本地假数据；再次运行375/390/393/430/1280基础布局/交互断言均通过。390×844补拍首屏、.shell内部定位后的夜间卡片与菜单，已目视核对。仅改评审文件，未修改产品。

### 已通过的修复

- 夜间地点标题计算色为rgb(233,237,246)，停留摘要为rgb(237,242,252)，截图可读；更多入口同步为浅色。原P1-1在测试夜间卡片中解决，尚不代表所有天空组合的完整对比度扫描通过。
- 菜单普通项为rgb(38,55,75)配rgb(243,246,250)，删除为rgb(173,37,50)配白底，菜单项44px高，删除有分隔。原P1-2解决。
- 390宽度下日期及时间输入均336px宽、16px字号，首屏完整显示2030/09/30及18:00；所有基础测试宽度仍通过首屏日期位置检查。原P1-3解决。代价是起点卡变高，390首屏汇总只露出上部，但不影响出发编辑。
- .arrival-hints实测flex-wrap:wrap；原P2-4的选择器问题解决。

### 200%内部溢出定位

方法：在390宽度下先读取每个元素的实际计算字号，再逐元素设为两倍；没有使用逐层继承的font-size:200%，避免指数放大。此为压力测试，不等同Safari文字缩放。

本轮documentElement.scrollWidth=390；.shell.clientWidth=390、scrollWidth=390。此前473px的.shell整体溢出已消失。仍有下列局部内容超出自身盒子：

| 元素 | 盒宽 / 内容宽 | 判断与建议 |
| --- | --- | --- |
| .station-number.start-number | 24px / scrollWidth 38px（30px字号） | 序号超出固定网格列14px。P2：起点网格首列用max-content或基于字体的宽度，确保与起点名称不重叠。 |
| .tf-rhythm-day | 74px / scrollWidth 90px | 日期区固定宽度不足。P2：扩大为max-content/minmax，或日期换行；完整节律展开时专项验证。 |
| .tf-rhythm-day > span（无class） | 74px / scrollWidth 90px（18px字号） | 实际溢出源是“9/30 周一”“10/1 周二”行，各超出约16px。应验证与右侧节律条间距，避免交叠。 |
| .vg-route-names | 143.98px / scrollWidth 1176px | overflow:hidden的路线摘要；内部30余字span（无class）宽775.69px，后续目的地span宽82.81/87.38px。这是有意省略展示，不计入.shell整体溢出，也不要求完整展开全部路线；必须保留其他位置的完整地点名。 |

建议增加断言：分别检查.shell内部宽度、起点编号与名称边界、展开节律的日期列与图条边界。不能仅比较根节点scrollWidth。当前剩余问题为P2局部字体放大适配，非原三项P1继续失败。

仍待：Safari真机200%文字放大、键盘与安全区；长图原尺寸四角可达性。未把这些标为通过。


## 最终复验定稿（2026-09-25）

结论：本轮要求复验的序号列、节律日期列以及新增planning-shortcuts首屏占位通过隔离Chrome检查。原复审发现的三项P1和两项P2在当前测试范围内关闭。此结论不包含Safari真机通过声明。

再次运行375/390/393/430/1280基础布局、停留、菜单、地图状态测试，全部通过。对四种手机宽度分别执行逐元素实际字号翻倍压力测试，并扫描.shell及可布局子元素边界、scrollWidth/clientWidth：

- .station-number.start-number、.tf-rhythm-day及其日期span不再出现在自身内容超宽列表；原24px/38px、74px/90px冲突消失。
- .shell的clientWidth与scrollWidth分别为375/375、390/390、393/393、430/430，无内部整体横向溢出。
- 唯一剩余内容超宽为有意省略的.vg-route-names及其被裁切的内联子节点；不属于关键字段被意外裁切，未影响页面宽度。

新增三按钮.planning-shortcuts实测为一行44px高。正常字号、844px视口高度下：

| 视口宽度 | 快捷区宽度 | 日期输入底边y | 时间输入底边y |
| --- | --- | --- | --- |
| 375 | 349px | 575.86px | 651.86px |
| 390 | 364px | 575.86px | 651.86px |
| 393 | 367px | 575.86px | 651.86px |
| 430 | 404px | 556.67px | 632.67px |

因此快捷按钮没有将日期、时间挤出首屏。首屏要求只针对正常字号；200%字体时允许纵向滚动，不以所有字段仍留首屏作为验收条件。

最终边界：外网资源被拦截，使用本地假数据与系统回退字体；Safari键盘、安全区、真实文字缩放、真实地图触摸及长图完整生成/四角可达性仍需对应环境验收。本轮未修改产品代码。
